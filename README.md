# ChiHongshu🍠

让 Agent 围绕你的问题研究小红书：检索笔记，逐张查看图片，核读评论，再形成有原帖来源的中文分析报告。

ChiHongshu 是可迁移的 **Skill 和本地证据辅助工具**。浏览器由用户选择，采集与分析由 Agent 执行；脚本负责整理、日期判断和一致性检查。展示名为 **ChiHongshu**，机器标识为 `chihongshu`。

## 使用

将本仓库作为一个完整的 `chihongshu` Skill 目录，放入宿主配置的技能目录。入口是 [SKILL.md](SKILL.md)，其余资源需保留相对路径。不同宿主的安装与发现方式以其当前说明为准；本仓库不会自动修改任何宿主配置。

也可以在支持读取本地指令的 Agent 中，直接指定本目录的 `SKILL.md`。例如：

```text
使用 ChiHongshu，研究小红书上 Agent 应用开发实习的真实工作内容。
重要关键词：Agent 实习、AI 应用开发实习。
重点看个人承担的工作、遇到的工程问题以及对下一段实习的帮助。
只纳入今年的帖子和评论。先让我选择浏览方式。
```

支持 `$skill` 调用的宿主可以使用 `$chihongshu`。Codex 的显示信息位于 [agents/openai.yaml](agents/openai.yaml)，其他宿主不依赖它。

## 浏览方式

每个新任务选择一次，已经指定就直接沿用；同一任务继续时不重问。

| 方式 | 前提 |
|---|---|
| web-access | 环境已有该 Skill 及其可用浏览器连接 |
| Agent 原生网页浏览能力 | 宿主实际支持原帖、图像与评论交互；仅搜索摘要不够 |
| Playwright MCP | 当前 MCP 工具可用，所连接浏览器具有所需登录状态 |
| ego-browser | 环境已配置对应 Skill/CLI，按当前版本指南操作 |

只加载所选方式的说明。不会自动安装四套工具，也不会未经用户选择切换浏览器或账号。首次真实研究会先用小样本检查能力，再扩大采集。

## 默认研究规则

- 按用户主题与重要关键词研究，可扩展关键词。保持页面默认排序。
- 每词覆盖 20–30 篇合格笔记，最多检查 100 个去重候选；跨词可复用本轮已读帖子，全局来源去重。
- 图片逐张查看；每篇最多纳入 30 条合格一级评论并展开相关回复，最多检查 100 个去重评论/回复节点。
- 无时间限制不加年份门槛；有时间限制则同时筛选帖子和评论。笔记优先采用编辑时间，无年份月日按采集当年解释，保留原始日期与依据。
- 结合问题覆盖、交叉支持、反例和最近 5 篇的信息增量判断是否停止，不自报虚构的置信度。最多补查两轮，每轮 1–3 个词。
- 视频只使用实际读到的标题、正文、封面、评论；不推断视频内容，不扩展到 GitHub、网盘等站外内容。
- 报告区分来源陈述、综合判断和适用条件，保留分歧。实质判断附原帖引用，不要求报告逐条展示图片或评论位置。
- 只读研究，保留登录态和用户原有页面。整体访问受阻时交付阶段稿；范围有限就如实说明。

这些是可覆盖的默认值。用户明确要求严格前 N 条时遵守其顺序与计数口径，不能按相关性挑选替代。

## 本地辅助脚本

辅助工具要求 Node.js 22+，仅使用内置模块，无需 `npm install`。当前实测版本和范围见 [VALIDATION.md](VALIDATION.md)。浏览器自身依赖另按所选工具配置。

在本仓库目录运行，研究输出必须位于仓库之外：

```bash
node scripts/init_research.mjs ../my-xhs-research
```

由 Agent 实际采集后填写 `research.json`、`sources.json`、图片等证据和 `report.md`。字段说明见 [证据与日期](references/evidence-and-dates.md)。初始化不会生成研究结果。

```bash
node scripts/build_source_index.mjs ../my-xhs-research
node scripts/validate_research.mjs ../my-xhs-research --final
```

去掉 `--final` 可检查收集中的数据，但草稿检查通过不等于可以交付。最终输出为：

```text
report.md             中文分析报告
source-index.md       作者、原帖、日期依据及阅读范围
research.json         需求、预算、查询、覆盖、判断来源与限制
sources.json          去重笔记、正文、图像记录和评论
evidence/             必要原图、截图和补充材料
checks.json           实际执行的一致性检查结果
```

检查脚本能够发现日期不符、重复记录、预算超限、缺图记录、漏引和陈旧索引。它不能证明图片已经真实核读、作者说法真实或结论足够有说服力，这些需要 Agent 实际阅读和语义复核。数据结构中的“已读”和“通过”不能预填。
