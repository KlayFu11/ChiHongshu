# 报告与检查

按用户侧重点组织报告，不机械堆砌逐帖摘要。先回答问题，再给来源陈述、综合判断、适用条件与反例。引用的作用是支持判断所用的依据，不能把作者自述的效果、经历或收入当作独立验证的事实。

每个依赖外部证据的实质判断直接链接已读原帖；注明是谁表达了该观点，评论者和笔记作者不得混淆。跨帖综合可以引用多个原帖。不强制报告列出图号/评论位置，证据记录仍保存足够上下文用于人工核对。

目的性样本不能推成全站占比或行业共识；帖子数、独立作者数、独立经历数不同。只在真实统计且分母明确时报告频次。没有资料支撑时明确“无法判断”，不为了满足用户期待而捏造建议。

## 交付流程

1. 写 `report.md`，同步 `research.json` 的问题、判断/来源映射、缺口与状态。
2. 人工核对引用内容是否足以支持对应判断，检查反例、归属、图片与评论的真实阅读范围，之后再填 `manualReview`。
3. 在 Skill 目录执行：

   ```bash
   node scripts/build_source_index.mjs /absolute/path/to/research
   node scripts/validate_research.mjs /absolute/path/to/research --final
   ```

4. 修正后仅重跑受影响的检查；证据或研究元数据变动后重新生成索引，防止陈旧索引。保留最终 `checks.json`。
5. 交付主报告和索引链接、实际覆盖及重要限制。只关闭确属本任务的页面。

`validate_research.mjs` 无 `--final` 时检查收集中数据一致性，草稿即使通过也始终 `readyForDelivery: false`。`--final` 额外要求完成状态、语义复核记录、已执行关键词、来源引用、索引新鲜度等。检查器验证记录之间的对应关系，不声称已经浏览、核读或证明作者可信；填写了错误记录仍可能通过，需要 Agent 真实执行。

报告的外部链接限原帖，若解释 Skill 文档或其他站外资料，放在研究报告以外。可使用相对路径链接本地证据；路径应在研究目录内。脚本检查基本 Markdown 内联链接，报告避免使用引用式链接或裸 URL 作为证据引注。

## 状态与异常

| 状态 | 含义与交付 |
|---|---|
| draft / running | 尚未采集或仍在研究，允许保存阶段材料，不能交付为最终报告。 |
| blocked | 登录、验证码、连接或关键工具能力阻止后续调查。给具体人工操作请求；继续不依赖阻碍的整理，未恢复前保持阶段稿。 |
| limited | 已完成可行调查但预算、结果不足或证据缺口限制结论；报告和结构化记录都披露限制，可交付有限报告。 |
| complete | 在约定范围内完成研究和语义检查；仍披露局部不可读、有限评论范围及样本偏差，不等于全站覆盖。 |

预算耗尽或搜索结果耗尽不能自动标记证据充分。整体阻碍不能通过把状态改成 limited 来绕过；必要时交付阶段稿并说明仍受阻。查询未完成、严格目标未满足不能谎称 complete。

## 创建时的验证边界

本包脚本和模拟数据可离线测试；四种浏览方式是按需适配指引，不是四套已实现并实测的自动爬虫。真实使用时对所选方式做小样本能力检查，记录工具/宿主/日期和通过范围。某一种成功不代表其他方式或其他宿主成功。
